# MultAI host runtime foundation

This private Node 24 library implements an independent local action gate and a file-backed SQLite execution journal. It does not execute commands, contact a provider, expose IPC, create worktrees or implement a desktop runtime. Native worker and collaboration-service integration still have to enforce the same boundaries.

An immutable versioned descriptor binds the original owner/device/session, account/session/runtime generations, inference connection and payer, canonical working directory, resource identity, exact operation, one-use request ID and expiry. Shell descriptors contain the absolute executable, exact argument array and reviewed command text; external operations bind transport, tool and JSON arguments. The deterministic SHA-256 includes every descriptor field. The host must resolve and revalidate filesystem paths before using them; lexical normalization here does not establish symlink safety or OS sandboxing.

`ExecutionJournal.prepare` records the descriptor without authorizing it. `decide` binds original-host approval to its reviewed fingerprint. `reserve` rechecks live Build mode and authority, consumes the approval and commits `executing` **before** the caller may dispatch anything. It returns either a one-use dispatch ticket or the saved result of an exact completed retry. The caller must dispatch at most once for a ticket and must never infer permission merely from a stored approval or an emitted tool event.

`complete` stores a bounded JSON outcome and its outbound completion event in the same SQLite transaction. Deliver `pending()` events until the service acknowledges their stable IDs, then call `acknowledge`. Delivery follows a monotonic SQLite insertion sequence, including equal timestamps and backward wall-clock changes. A replay cannot change a previously stored result or event payload. Empty or redacted output must not be treated as a filesystem backup.

The caller must invoke `invalidateSession` at Stop, sign-out, disconnect, sleep, connection/account change, runtime replacement and Quit. This cancels prepared authority and makes executing calls uncertain. Opening the file also changes interrupted calls to `uncertain` and cancels remaining pending or approved prepared actions. Explicit rejections remain rejected through recovery and invalidation. An uncertain effect blocks further dispatch in that session; human recovery tooling is deliberately not implemented yet, and no side effect is automatically retried. A changed authority during completion makes the call uncertain and rejects the stale callback.

Use one journal per account/service/device inside the OS application-data directory. Scope metadata prevents opening another scope's journal. The native host must supply a trusted parent directory that other users and untrusted processes cannot replace; existing parent-directory permissions are not changed. The database file is created privately with mode `0600` or secured through its opened descriptor before SQLite opens it. Symbolic links and nonregular database paths are refused, using `O_NOFOLLOW` where supported. SQLite uses an exclusive connection lock to prevent a second executor from opening the same file, `synchronous=FULL` and transactional updates. Journal contents are **not encrypted**; never store credentials in descriptors, output or outbound events. Redaction and reviewed sharing remain host/service responsibilities.

Results are limited to 64 KiB and event payloads to 128 KiB. The journal stops accepting new records after 10,000 effects or 10,000 retained outbound events, or 64 MiB of outbound payloads. It never silently drops pending delivery or idempotency history. Explicit reviewed retention/cleanup and privacy-preserving diagnostics remain future work.

Run `npm test --workspace @multai/runtime` for real temporary SQLite reopen, single-executor, Plan/Build, permission, generation, changed-byte, expiry, one-use and outbox tests. These establish local library behavior; they do not establish native runtime or real provider acceptance.

The initial journal schema is version 2. Pre-release version 1 journals are refused rather than automatically migrated; preserve any such local file for explicit review. No deployed journal database is being upgraded by this scaffold.
