# Controlled inference and local effects

This fresh host-local implementation supports four explicitly selected protocol paths: OpenAI API Responses, official ChatGPT OAuth Responses, Anthropic Messages and OpenAI-compatible Chat Completions (including a manually selected Kimi endpoint). A compatible protocol is not a universal provider or subscription guarantee. No native CLI, user profile, unmanaged hosted tool, MCP server or provider SDK is loaded.

`runAgent` receives an explicit model, scoped credentials, bounded text context, tool definitions and a trusted `executeTool` callback. It streams text while waiting for a terminal provider success before dispatching complete tool calls serially. It has per-response byte/event/text/idle/deadline limits, an overall input-byte bound, and turn/tool caps. It never retries a request, grants tool authority, reads provider credentials from the environment, or runs an effect by itself. Unknown tools and incomplete/failed streams fail closed. Cumulative usage is reported only while each completed provider turn supplies the relevant measurements; missing usage is unknown.

The app must revalidate central session/owner/device/connection/model/generation grants before every provider request and tool operation, abort old work on any lifecycle change, and redact tool arguments/results before sharing activity. The runtime `onEvent` tool events are private host records. A caller must not expose them as trusted renderer authority.

Known ChatGPT plan-limit/unavailable codes are preserved through bounded HTTP error bodies and SSE error envelopes so the UI can offer the documented recovery. Raw provider messages/bodies and unrecognized codes are never exposed. Claude block completion and compatible-provider finish markers must agree with tool calls before any callback is dispatched.

`discoverModels` uses the selected connection's live provider catalog. ChatGPT uses `https://api.openai.com/v1/models`, keeps `visibility: list` rows in server order, and sends the selected slug to the public Responses endpoint. ChatGPT requests always use `store:false` and `stream:true`, omit unsupported preview parameters, send full input history and group app functions under the `multai` namespace. Complete reasoning/output items are retained across tool turns; Claude's signed thinking blocks and compatible-provider reasoning content are preserved privately as protocol state.

`ControlledWorkspace.open` accepts an already created **private working copy** chosen by the trusted host, never an original checkout or participant path. It provides bounded list/read/literal search and exact-hash atomic text replacement. Traversal, links/hardlinks, special files, credential paths/formats, binary and oversized content are unavailable. Root/parent/file identity and expected content are rechecked before saving. Parents must exist; the library does not silently create directory trees. The native host must own the private parent directories and serialize effects. These path checks are defense in depth, not a sandbox against another process with the same OS user's unrestricted access. Files are not encrypted by this library.

`write(path,text,expectedHash,{descriptor,authority,journal,signal})` requires the exact file-write descriptor and independent live original-host Build authority. It reserves and completes the SQLite journal internally. `executeApprovedShell` does the same for an exact canonical executable/argv/cwd descriptor, uses a minimal credential-free environment, bounds/redacts final output, and kills the owned POSIX process group on cancellation/deadline or completion. A reviewed shell command has the executing OS user's permissions. Windows shell dispatch is unavailable pending actual process-tree verification. No shell profiles or secret environment values are inherited.

Atomic replacement preserves an existing file's ordinary read/write/execute mode bits and removes special bits; a new file starts at `0600`. The effect helpers conservatively require a still-valid descriptor when invoked, including for completed-result reuse. An expired helper invocation does not rerun the effect; its saved record remains inspectable privately through the host journal. No owner-facing reconciliation operation currently clears an uncertain effect. A validation failure after reservation can therefore require a new reviewed session instead of an automatic retry; Resume alone does not prove the uncertain state is resolved.

Specifically, `write` reserves its journal entry before checking the current file hash and parent path. A stale-file/preflight rejection leaves that entry executing until the coordinator invalidates it or the journal reopens, when it becomes uncertain. Further mutating reservations for that session are then blocked even if the rejected write made no file change. Read-only inspection remains possible, but this build has no safe in-app operation to reconcile that record and restore mutation authority. Do not delete/edit the journal or automatically repeat the write to bypass this state; preserve the working copy for explicit human review.

The caller must first obtain and consume any **central** one-use action grant, then call these effect helpers. It must not pre-reserve the **local** journal: the helper owns that reservation. Completed exact retries return the saved result; failures after reservation remain executing until invalidation/reopen marks them uncertain. Uncertain effects require human review and never automatically repeat. Cancellation may preserve partial work.

Protocol/state tests use synthetic responses and keys; workspace/journal tests use real temporary files, and shell tests launch real local Node processes with reviewed descriptors. These tests do not establish successful live provider billing, Google/ChatGPT browser consent, production cloud deployment, signed installers or cross-platform native acceptance.
